Frozen numerical convention to implement and test
Treat validated source minute timestamps as bar starts; if source uses end timestamps, normalize only after confirming metadata and audit transformed grid. For a complete full session, UTC→America/New_York yields exactly minute starts 09:30,...,15:59 (390 strictly increasing unique minutes). Let O_0930 be the first minute's valid open, and C_t each minute close. For a day d define 390 one-minute within-session log increments:
r[d,0] = log(C[d,09:30] / O[d,09:30])
r[d,j] = log(C[d, minute j] / C[d, minute j-1]), j=1,...,389
rv[d,k] = sum_{j=5k}^{5k+4} r[d,j]^2, k=0,...,77
RV_day[d] = sum_{k=0}^{77} rv[d,k]
q[d,k] = rv[d,k]/RV_day[d], if finite and RV_day[d]>0
RV_open[d] = sum_{k=0}^{5} rv[d,k]
At e.g. 09:35 the one-minute return uses the close at the 09:35 boundary (prior bar 09:34) and the close at 09:36 (bar 09:35); this interval belongs to the new five-minute bin. The 09:30 open-to-close term excludes overnight movement. Do not mix 389 close-to-close returns with 390-bin accounting, do not set the opening term to previous-day close, and do not count a cross-boundary return in two bins. Within-session numerator and daily denominator use the identical squared increments. This is realized variance (sum of squares), not the square-root RV or logged state from Experiment B.
